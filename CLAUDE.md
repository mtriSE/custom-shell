# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A POSIX-style shell in C++23, written from scratch. Docs, comments and commit messages are written in English.

## Commands

- Build + run: `./run.sh` (cmake configure + build, then execs `build/shell`).
- Rebuild only: `cmake --build build`
- Terminal tests: `tests/pty/run.sh` (needs `build/shell` and `python3`; runs the shell on a pty). `tests/run.sh` runs them after the golden cases.
- Regression tests: `tests/run.sh` (needs a built `build/shell`). Each `tests/cases/<name>.in` is piped to the shell on stdin, stdout+stderr are diffed against `<name>.out`, in a scratch temp dir. `tests/run.sh --update` rewrites all `.out` files — review the git diff afterwards. To run one case, copy it to a temp dir and run `build/shell < case.in` manually (the script has no filter).

Prerequisites (install before the first build): CMake >= 3.13, a C++23 compiler (GCC 13+ / Clang 17+ recommended) and the GNU readline *development* package. Debian/Ubuntu: `sudo apt install build-essential cmake libreadline-dev`; Fedora/RHEL: `sudo dnf install gcc-c++ cmake readline-devel`; Arch: `sudo pacman -S --needed base-devel cmake readline`; `python3` (standard library only) for the terminal tests in `tests/pty/`; the full list (openSUSE, Alpine, Void, Gentoo, Nix) is in README.md. A build error `readline/readline.h: No such file or directory` means the dev package is missing; do not work around it, install it (ask the user to run it, since it needs sudo).

`CMakeLists.txt` globs `src/*.cpp` and `src/*.hpp` recursively, so new files are picked up after re-running cmake. It links `readline`, which provides line editing and TAB completion when stdin is a terminal.

## Architecture

`main` → `Shell::run()` (`shell.cpp`) is a read-parse-execute loop that carries `last_status_` (for `$?`) between lines.

- `read_line` (`shell.cpp`): uses `readline("$ ")` when stdin is a tty, otherwise prints the prompt and uses `std::getline`. The split is deliberate: readline echoes input on non-tty stdin, which would break `tests/run.sh`, so TAB completion can't be tested there (drive the binary through a pty instead).
- `signals.cpp`: when stdin is a tty, SIGINT is caught (the handler writes a byte to a non-blocking pipe, `interrupt_fd()`), SIGQUIT is caught by a no-op, SIGTSTP is ignored (stop-gap until job control). No project or readline dependency. `completion.cpp` `init_readline` sets `rl_catch_signals = 0` and `rl_getc_function` to a reader that polls stdin and that pipe: Ctrl-C at the prompt clears the line (after ESC/Ctrl-X or in Ctrl-R the reader first returns Ctrl-G so readline drops that state, then the `'\n'`), `prompt_was_interrupted()` tells `Shell::run`, which sets `$?` to 130 and skips the line. For foreground commands `execute()` and `run_stages` report death by SIGINT/SIGQUIT in `Outcome::interrupted` (waits retry on `EINTR`), and `Shell::run` then prints one newline when interactive; forked stages call `reset_child_signals()` first.
- `completion.cpp`: `rl_attempted_completion_function` hook. In command position (no words before the cursor) it completes builtin names (`builtin_names()` in `builtins.cpp`) plus executables in `$PATH` (`executables_in_path()` in `path_utils.cpp`, rescanned on every TAB, unreadable dirs skipped), deduplicated, with `rl_attempted_completion_over = 1` to block readline's filename fallback. For arguments, if the line's first word has a script registered via `complete -C` (`find_completer()`), the script is run (`capture_lines()`, no timeout, but Ctrl-C kills the script's own process group and drops that completion; the line stays as typed) as `script <command> <word being completed> <previous word>`, with `COMP_LINE` (whole line) and `COMP_POINT` (cursor byte offset) set in the child only, and each stdout line is a candidate, again without filename fallback. Otherwise the hook returns `nullptr`, so readline's built-in filename completion runs (for any command, nested paths and directories included). With several matches the first TAB rings the bell and the second lists them via `display_matches` (one line, two spaces apart; readline sorts and dedupes). Both sources fill the file-scope `candidates`, which one `candidate_generator` hands to readline.
- `parser.cpp`: single-pass state machine (Normal / SingleQuote / DoubleQuote) that turns one line into a `Command` (`args` + ordered `redirects`). Handles quoting, backslash escapes, `$?` expansion, redirect operators (`>`, `>>`, `N>`, `>&N`), an unquoted `|` that splits the line into the `stages` of a `Pipeline`, and a trailing unquoted `&` word (`Pipeline::background`). An empty stage is a syntax error. Syntax errors return `nullopt` plus a message, and the shell sets status 2.
- `runner.cpp` `run_pipeline` (the execution half, split from `shell.cpp`; `Outcome` is in `runner.hpp`): one stage runs as before; several stages are forked together (`run_stages`), each wired to the neighbouring `pipe()` ends by `dup2` before its own redirects, all pipe fds closed in the children and in the parent (or readers never see EOF), then the parent waits for all and takes the last stage's status. Builtins in a stage run in the child; `a | b &` runs in the foreground for now.
- `runner.cpp` `run_command`: applies redirects *first*, then dispatches builtin → external (via PATH) → "command not found" (127). Applying redirects before dispatch is what makes them work uniformly for all three.
- `redirect.cpp` `FdRedirect`: RAII wrapper that `dup2`s a real file descriptor and restores it on destruction. Redirection works at the fd level (not by swapping stream buffers), so builtins writing to `std::cout`/`std::cerr` and forked children both follow it. `RedirectStack` in `runner.cpp` holds them and must unwind in reverse order, because multiple redirects on the same fd each saved the previous state. Saved fd copies live at fd 10 and up, so the parser caps user fds at 9 (`MAX_FD`).
- `builtins.cpp`: table of `exit`, `echo`, `type`, `complete`, `jobs`, `pwd` (prints `std::filesystem::current_path()`), `cd` (a plain `chdir`, with the error text from `errno`; `~`, `~/path` and bare `cd` use `$HOME` via `expand_tilde`, but this is not tilde expansion for the whole shell; it runs in the shell process so the cwd really changes, except inside a multi-stage pipeline where it runs in a child). `jobs` lists the jobs in `job_table.cpp` in the bash format `[1]+  Running                 sleep 10 &`; `print_jobs()` first reaps finished jobs with `waitpid(WNOHANG)`, shows them once as `Done` (no trailing `&`) and drops them from the table; `Shell::run` also calls it with `only_done` before every prompt. `complete -C <script> <command>` stores the script in `completer_registry.cpp` (the args are already whitespace-split by the parser); `complete -p` reprints specs from there as `complete -C '<script>' <command>`, or reports "no completion specification"; `complete -r [command...]` removes them (all of them without names), silently. `type` uses `path_utils.cpp` (`find_in_path`) for PATH lookup, which `shell.cpp` also uses.
- `executor.cpp`: fork/exec of the resolved executable, returns its exit status. `exec_replace()` is the exec-in-place used by pipeline stages. `spawn()` does the fork/exec without waiting and returns the pid (background jobs; reaped by `print_jobs()`); when interactive the child gets its own process group so terminal keys do not reach it. `Shell::run` registers the job (`announce_job`: `add_job` with the line as typed) and prints `[N] pid` after the command's redirects are undone. `capture_lines()` does the same with stdout piped back and returns the output lines (used for completer scripts).

`main.cpp` sets `std::unitbuf` on cout/cerr so output is flushed before a child process writes, keeping ordering correct.
